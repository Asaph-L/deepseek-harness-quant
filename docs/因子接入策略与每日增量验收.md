# 因子接入策略与每日增量验收

> 状态：执行基线 v1（2026-08-24）。本文定义准入顺序、停机条件和可下放任务的完成终点；不记录未经当前证据链复算的历史收益结论。

## 1. 决策原则

1. **研究有效不等于可交易**。横截面因子必须依次通过：PIT 面板完整性 → 训练期方向冻结 → 独立 holdout 确认 → T+1 开盘统一撮合回测 → archive v2 身份与完整性校验 → registry `strategy_eligible=true`。
2. **主仓与卫星仓分离**。`turn_low` 只在自身正式回测重新通过后作为分散主仓候选；高分新因子只能进入有上限的卫星仓，不能覆盖主仓或产生第二套买入指令。
3. **唯一买入出口**。因子只形成证据和目标权重；最终买入仍由 L2 决策卡片聚合输出。
4. **默认拒绝旧证据**。面板 schema、面板 run、数据指纹、实现指纹、策略因子集合或 archive hash 任一变化，旧准入自动失效。
5. **当前不接入历史候选权重**。包括 `agp_amihud_max3_abs_csrank` 在内的旧候选，在本轮 QFQ/PIT/正式回测链完成前保持 research-only；禁止仅依据旧报告写入生产权重。

## 2. 单一准入状态机

```text
configured
  → panel_ready
  → evidence_eligible
  → holdout_confirmed
  → execution_backtest_accepted
  → strategy_eligible
  → satellite_shadow
  → satellite_live
```

任何门失败都回到 `candidate`，并保留结构化 reason code。人工锁可以保护生命周期备注，不能绕过证据门。

`satellite_shadow` 至少观察一个完整再平衡周期；只有实时输入、候选生成、目标权重和 L2 卡片同源，且没有漂移告警时才允许进入 `satellite_live`。实盘权重上限必须来自配置，不得写在 Python 或页面中。

## 3. 因子目录的数据合同

`config/factors.yaml` 是横截面因子的唯一业务目录；实现函数仍是代码能力 allowlist，但默认计算集合和业务元数据只来自配置。每个条目必须且只能声明：

- `id`、`enabled`、`implementation`
- `family`、`default_direction`、`kind`、`frequency`
- `required_datasets`、`available_from`
- `implementation`

实现的 callable、调用方式（`call_mode`）和允许的数据集属于代码侧安全
allowlist，配置不能指定函数参数或发明数据集；目录声明的 `required_datasets`
必须与代码契约精确一致。

活动配置与 `.example` 必须逐字节同步。活动文件缺失可读取模板；活动文件存在但 schema/字段无效、重复键/ID、未知实现、实现归属不一致或目录不完整时必须 fail-closed，不能回退到模板或代码内置列表。面板 manifest 和正式回测数据指纹绑定每个输入文件的 SHA-256；SQLite 输入同时绑定主文件、`-wal` 和 rollback journal 的字节身份。目录或尚未 checkpoint 的已提交 WAL 发生变化，旧面板和旧正式回测证据都必须自动失效。

`default_direction` 只是旧调用方的兼容先验。正式证据的方向仍只由训练期冻结，holdout 不得反向修改方向；本次目录化不改变任何因子公式，也不把因子写入生产权重或准入状态。

## 4. 每日增量 DAG 的完成定义

盘后入口只允许一条 DAG、一个共享写锁。建议顺序如下：

1. 交易日历确认目标日期；非开市日只更新状态，不伪造分区。
2. 写入 qfq 日线增量；验证 exact key、价格、收益率、换手、ST 和与上一实际观测日的连续性。
3. 更新因子所需披露数据；每个数据源必须有独立 watermark，能区分“查询为空”和“尚未查询”。
4. 运行 bars/source quality gates；关键数据不完整时停止下游。
5. 增量刷新面板或明确使旧 panel manifest 失效；禁止继续消费数据指纹已变化的面板。
6. 生成 factor evidence，并校验 artifact 日期、schema、run identity 和完整性。
7. 同步 registry；只有当前 evidence 与当前正式 backtest 双绑定的因子可获得 `strategy_eligible`。
8. 生成唯一日信号、L2 决策层、机会扫描、风控、跟踪和日报。

任务成功不能只看进程退出码。命令型节点必须证明预期 artifact 在本次运行中被刷新，并且 artifact 的 `data_date` 等于目标交易日。

## 5. 数据源增量的硬门

- 龙虎榜：`top_inst` 使用官方 `exalter/side/reason` 字段；以交易日 watermark
  记录成功、空结果或失败。20:15 前的成功也只能是 provisional，之后必须复查；
  失败不可返回 0 冒充成功。
- 股东户数：不能用“该股票历史上出现过”作为永久完成标志；按自然日扫描
  公告窗口（含周末），近期日期强制复查；更正计算只能使用当时已经公告的上一报告期。
- 社保持仓：按报告期和股票记录 coverage，保留同一报告期的全部公告版本；
  每日一个总限额内轮询最近两个已结束季度，以覆盖 150 天更正窗口。只有
  confirmed-empty 可以生成 0，provisional/failed/未查询保持未知。
- 财报：只按 `ann_date` 生效；无公告日的数据不得进入精确 PIT 因子。
- 换手：`available_from` 不早于 2019-01-01；任何 2019 年前换手结论直接拒绝。
- 市场生命周期：`config/params.yaml:market_lifecycle` 是正式回测与历史状态
  修复的唯一真源。当前 `.BJ` 代码在 2021-11-15 前属于本项目交易所可投域之外；
  eligibility 必须为 false。历史 ST 修复对这些 pair 只允许保留冻结快照原值并写入
  显式 `not_applicable_preserve_source` 证据，不能因备用 provider 不支持 BJ 或名称
  变更查询为空而填 0；生效日及之后仍缺真实状态证据则 fail-closed。
- 证券代码变更：`config/security_code_changes.yaml` 是同一上市主体换码后的唯一连续性
  配置。只有 provider 已在新代码下提供完整回填历史，且旧/新代码的重叠成交量、成交额、
  换手率、涨跌幅与历史市值逐期一致时，才允许保留 canonical 新代码并过滤旧代码；否则
  fail-closed。活动配置与 `.example` 必须一致，面板 source identity、builder identity 和
  正式回测 data/implementation identity 必须同时绑定该合同。

以上任一数据源不满足自己的 coverage 合同，只影响依赖它的因子，不应把缺失值填成零或让无关因子全部失效。

## 6. 页面增强的边界

页面只消费 API，不裁决业务状态。API 至少返回：

- 当前 panel/evidence/backtest/registry 的 schema 与 run identity；
- 各准入门状态、reason codes 和更新时间；
- 数据源 coverage、水位和 stale 状态；
- 主仓/卫星/研究三类角色与配置权重上限；
- launchd/DAG 配置漂移和最近一次失败节点。

前端不得根据中文文案推断是否可交易，也不得硬编码因子、策略、阈值、任务或状态列表。网络超时必须真实中止请求，并以“数据不可用”显示，不能复用过期值伪装为最新。

披露源状态探针、面板计算和正式回测必须以只读但 **WAL-aware** 的 SQLite 连接读取；`immutable=1`
会忽略未 checkpoint 的 WAL，禁止用于仍可能变化的数据源。健康灯只评估配置指定数量的
最近分区，并按各源配置的最大陈旧小时数降级；历史失败不能永久污染，陈旧的
单条 complete 也不能永久冒绿。所有进入 `innerHTML` 的 API/SQLite 文本必须做
真正的 HTML entity escape，字段兜底函数不等于转义函数。

## 7. 可下放工作包与明确终点

### F1：动态因子目录

范围仅限目录 loader、活动/模板配置、直接消费者和离线测试。终点：业务因子列表/族/方向先验/数据依赖不再硬编码；配置无效 fail-closed；API 目录同源；测试不写运行数据。

### F2：披露数据每日增量

范围仅限龙虎榜、股东户数、社保抓取器及其 DAG 配置/水位测试。终点：幂等、断点续传、空结果可证明、失败非零退出、历史 catch-up 与单日运行分离；不执行真实全量抓取。

### F3：面板增量与证据失效

范围仅限 alpha panel manifest/分区和 daily adapters。终点：新增交易日只计算受影响尾窗；任何源变更使旧 manifest 明确失效；中断不会发布混代面板；与全量重算在合成数据上逐值一致。

### F4：准入到卫星影子仓

必须在本轮正式证据产出后开始。终点：一个指定因子拥有当前 evidence + 当前 archive 双绑定；registry 准入；配置化卫星上限；影子组合与主仓分别归因；L2 仍是唯一买入出口。若任何 gate 未通过，交付结果应是“保持 research-only”及精确 reason codes，而不是降低门槛。

### F5：页面证据链

范围仅限只读 API、页面渲染和契约测试。终点：用户能从因子一路追到 panel run、evidence run、backtest run/archive hash、registry 状态和每日 DAG 水位；缺失或漂移明确显示红灯；不增加前端业务常量。

## 8. 本轮执行顺序

代码侧动态目录、披露增量合同、状态页面、HARNESS 派单桥和无副作用快速回归
已先完成离线加固；它们不构成收益结论。真实证据仍严格按下列顺序：

1. 补齐独立 ST repair staging，续跑 adj-factor stage。
2. 重建并审计 0-break QFQ 候选，完成 publish dry-run。
3. 原子发布候选并做真实 rollback/re-publish 演练。
4. 构建 `pit-contract-v3-canonical-units` 完整不可变面板代际。
5. 运行 `turn_low` 正式 T+1 回测并冻结 archive identity。
6. 在代码、数据、配置不再变化后运行 evaluator v2。
7. 同步 registry；只按真实 reason codes 决定是否存在可进入 F4 的因子。
8. 验证每日 DAG、状态 API/页面和 launchd 单一调度无漂移。

不得为赶进度交换第 5、6 步，也不得先写生产权重再补证据。
